# 奇妙日需求规格说明书

## 1. 引言

### 1.1 编写目的

本文档用于说明“奇妙日”项目的业务目标、功能需求、非功能需求、约束条件与验收要求，作为开发、测试、交付和后续迭代的依据。

### 1.2 项目背景

奇妙日是一个基于 UniApp 开发的跨端倒数日应用，支持 H5 与微信小程序。系统主要用于记录和管理重要日期、重复事件、纪念日、计划节点，并支持分类管理、日历查看、个人中心、微信登录与分享等功能。

### 1.3 术语说明

- **奇妙日**：用户记录的一条倒数日/纪念日/计划日程数据
- **奇妙本**：分类聚合与日程集合的概念表达
- **关怀模式**：针对视力较弱、老年或阅读困难用户优化的界面模式
- **BuildAdmin**：后端使用的管理与接口支撑框架

## 2. 总体描述

### 2.1 产品目标

- 支持用户在 H5 和微信小程序中统一使用倒数日能力
- 帮助用户记录未来计划与已发生纪念事件
- 提供重复事件能力，满足长期提醒/打卡/复诊等场景
- 提供更友好的视障适配能力，包括关怀模式和字体调节
- 支持分享、版本升级、登录留存等产品能力

### 2.2 用户特征

- 普通个人用户
- 健康管理用户
- 学生/考试用户
- 纪念日管理用户
- 视力不佳或中老年用户

### 2.3 运行环境

- H5 浏览器环境
- 微信内 H5 环境
- 微信小程序环境

### 2.4 设计与实现约束

- 前端基于 UniApp + Vue3 + TypeScript
- 后端接口依赖 BuildAdmin
- 微信相关能力需满足平台规范
- 正式环境需使用 HTTPS 与合法域名配置

## 3. 功能需求

### 3.1 用户与登录模块

#### FR-001 用户登录

系统应支持用户通过账号密码方式登录。

#### FR-002 微信登录

系统应支持：

- H5 微信登录
- 微信小程序登录

#### FR-003 用户注册

系统应支持新用户注册与初始信息录入。

#### FR-004 个人信息补全

当系统发现用户生日等关键信息为空时，应提示用户前往补全。

#### FR-005 登录留存统计

系统应在用户登录后累计登录天数，并用于展示留存数据。

### 3.2 倒数日管理模块

#### FR-006 新建倒数日

用户应能够创建新的倒数日，包含：

- 标题
- 日期
- 分类
- 是否置顶
- 重复周期
- 重复频率

#### FR-007 编辑倒数日

用户应能够修改已有倒数日信息。

#### FR-008 删除倒数日

用户应能够删除倒数日。

#### FR-009 查看倒数日详情

用户应能够查看倒数日详情信息。

#### FR-010 归档倒数日

用户应能够将倒数日归档，并在归档管理中查看与恢复。

#### FR-011 置顶倒数日

用户应能够置顶和取消置顶倒数日。

#### FR-012 重复事件计算

系统应支持以下重复频率：

- 不重复
- 天重复
- 周重复
- 月重复
- 年重复

并自动计算未来最近一次日期用于展示。

### 3.3 分类管理模块

#### FR-013 分类列表

系统应支持查看分类列表。

#### FR-014 分类增删改

系统应支持分类的新增、编辑和删除。

#### FR-015 按分类查看倒数日

系统应支持用户按分类聚合查看倒数日内容。

### 3.4 展示与浏览模块

#### FR-016 首页展示

首页应支持：

- 置顶区展示
- 未来区展示
- 已经区展示
- 列表/格子布局切换

#### FR-017 日历页展示

系统应支持按日期查看倒数日数据。

#### FR-018 个人中心展示

系统应支持个人信息、统计数据、累计登录天数、设置项和归档管理展示。

### 3.5 分享与传播模块

#### FR-019 分享能力

系统应支持 H5 微信分享或详情分享能力。

#### FR-020 页面转发配置

系统应支持为关键页面补充转发配置。

#### FR-021 分享后台可配置

系统应支持未来将分享文案、分享图或海报能力配置化。

### 3.6 关怀与可访问性模块

#### FR-022 关怀模式

系统应支持关怀模式，优化字体大小、对比度和可读性。

#### FR-023 字体大小调节

系统应新增字体大小设置功能，满足视力较弱用户需求。

#### FR-024 编辑按钮可识别性优化

系统应优化编辑符号与编辑入口的视觉显著性，提升识别度。

> 备注：该项来源于 README 中“照顾眼神不好的用户，字体大小需要可以调节，编辑符号不明显不易识别”的需求，预估工作量 2 天。

### 3.7 扩展功能需求

#### FR-025 快捷添加 120 岁倒数日

系统应支持检测是否存在“120 岁倒数日”，若不存在则提供快捷添加能力。

#### FR-026 小程序版发布

系统应支持微信小程序版构建与正式发布。

#### FR-027 闹钟应用测试

系统应对闹钟/提醒相关应用场景进行联动性验证或可行性测试。

#### FR-028 订阅消息能力预研

系统应支持订阅消息能力的接入预研，包括订阅模板、跳转链接与用户确认流程。

## 5. 非功能需求

### 5.1 性能要求

- 首页进入后应在合理时间内完成列表展示
- 分类页、个人中心、日历页切换应流畅
- H5 和小程序端均应保证基本交互响应速度

### 5.2 可用性要求

- 页面导航清晰
- 登录流程可理解
- 关怀模式与字体调节功能应易于发现和使用

### 5.3 可维护性要求

- 模块划分清晰
- 接口统一由服务层封装
- 文档可持续更新

### 5.4 兼容性要求

- 支持 H5
- 支持微信小程序
- 重点验证华为 nova 5 Pro 等机型底部布局兼容问题

### 5.5 安全性要求

- 登录信息与 token 应妥善存储
- 微信相关密钥不得暴露在前端
- 生产环境必须使用 HTTPS
