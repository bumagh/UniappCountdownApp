# 奇妙日概要设计说明书

## 1. 概述

本文档描述奇妙日前端系统的总体设计方案，重点说明系统架构、模块划分、关键流程、接口组织方式与跨端适配设计。

## 2. 建设目标

- 基于 UniApp 实现 H5 与微信小程序双端统一开发
- 形成倒数日、分类、个人中心、登录注册、分享等完整能力闭环
- 通过 BuildAdmin 后端接口支撑业务数据
- 在单人兼职开发场景下保持结构清晰、易于维护和快速迭代

## 3. 总体架构

系统采用“页面层 + 组件层 + 服务层 + 基础设施层 + 后端接口层”的分层结构。

### 3.1 页面层

负责业务编排、用户交互和页面展示。

- 首页 `pages/index/index.vue`
- 分类页 `pages/categories/categories.vue`
- 日历页 `pages/calendar/calendar.vue`
- 个人中心 `pages/profile/profile.vue`
- 登录/注册/编辑/详情等分包页面

### 3.2 组件层

负责通用 UI 复用与局部功能抽象。

- `CountdownCard.vue`
- `FloatWechatLogin.vue`
- `RepeatSelector.vue`
- `ShareCountdown.vue`

### 3.3 服务层

负责统一封装所有接口调用。

- `apiService.ts`
- `wechatService.ts`

### 3.4 基础设施层

负责请求、环境、工具、主题和平台差异处理。

- `request.ts`
- `axios.ts`
- `config/api.ts`
- `countdownUtils.ts`
- `db.js`
- `theme.ts`

### 3.5 后端接口层

基于 BuildAdmin 提供：

- 用户接口
- 分类接口
- 倒数日接口
- 登录天数接口
- 版本接口
- 微信配置接口

## 4. 模块设计

### 4.1 应用启动模块

负责：

- 创建应用实例
- 版本校验
- 清理缓存
- 获取系统信息
- 完成应用初始化

### 4.2 登录与注册模块

负责：

- 账号登录
- 微信登录
- 注册
- 用户信息补全

设计特点：

- 区分 H5 与小程序登录流程
- 小程序环境需适配微信用户信息获取策略

### 4.3 首页模块

负责：

- 展示倒数日主列表
- 按置顶、未来、已经三类组织数据
- 支持格子/列表切换
- 支持关怀模式切换
- 处理登录天数更新逻辑

### 4.4 分类模块

负责：

- 分类展示
- 分类统计
- 按分类查看倒数日

### 4.5 日历模块

负责：

- 按日期视图聚合倒数日

### 4.6 个人中心模块

负责：

- 用户资料显示
- 数据统计
- `loginDays` 展示
- 关怀模式、提醒、归档管理、数据导入导出

### 4.7 倒数日详情与编辑模块

负责：

- 创建倒数日
- 编辑倒数日
- 查看详情
- 分享
- 归档与置顶处理

## 6. 关键流程设计

### 6.1 启动流程

1. 应用启动
2. 请求版本信息
3. 若版本变化则清理本地缓存并重新登录
4. 获取系统信息
5. 渲染页面

### 6.2 首页数据加载流程

1. 进入首页
2. 判断登录态
3. 若已登录则更新登录天数
4. 加载用户信息
5. 加载分类信息
6. 加载倒数日列表
7. 计算显示日期和分组
8. 渲染页面

### 6.3 个人中心流程

1. 进入个人中心
2. 加载用户信息、统计和归档数据
3. 从 storage 读取 `careMode`
4. 从 storage 读取 `loginDays`
5. 展示用户信息与设置项

## 7. 跨端适配设计

### 7.1 H5

- 自动根据当前域名拼接请求基地址
- 支持微信内 H5 分享
- 支持浏览器缓存清理与 Service Worker 清理

### 7.2 微信小程序

- 小程序环境使用独立登录 API
- 小程序环境请求走独立条件编译分支
- 需配置合法域名与平台能力

## 8. 可访问性设计

项目现有设计已包含关怀模式，后续概要设计中建议补充：

- 字体大小调节设置
- 编辑按钮增强可见性
- 关键按钮更大点击区域
- 更强色彩对比度

## 9. 风险与设计关注点

- storage 键名存在历史不一致问题
- 登录天数存在服务端与本地缓存双来源
- 分享与转发配置尚需进一步标准化
- 单人兼职开发下应优先保证核心闭环与稳定性

## 10. 后续概要设计建议

- 增加统一的设置中心
- 增加统一错误提示与异常码映射
- 将平台差异逻辑继续向基础设施层收敛
- 将订阅消息、模板消息能力抽象为独立模块
