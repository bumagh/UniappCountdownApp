# 奇妙日时间精度升级技术方案

## 1. 文档目的

本文档用于描述奇妙日（Countdown）从“日期精度”升级到“小时分钟精度”的前后端数据结构、页面改造点、公共逻辑调整方案、兼容策略、测试方案与实施步骤。

## 2. 当前现状

### 2.1 当前数据结构

当前 `Countdown` 类型定义如下：

- `title`
- `date`
- `category_id`
- `user_id`
- `is_pinned`
- `repeat_cycle`
- `repeat_frequency`
- `is_archived`

现状问题：

- 仅有 `date: string`
- 无 `time` 或 `datetime`
- 倒计时计算逻辑以“天”为主
- 表单 `AddCountdown.vue` 只有日期选择器，没有时间选择器

### 2.2 当前受影响模块

直接受影响模块包括：

- `types/index.ts`
- `src/components/AddCountdown.vue`
- `src/components/CountdownCard.vue`
- `src/pages/index/index.vue`
- `src/pages/calendar/calendar.vue`
- `subpackages/detail/detail.vue`
- `src/services/apiService.ts`
- 后端倒数日增删改查接口

间接受影响模块包括：

- 排序逻辑
- 重复事件计算逻辑
- 日期格式化工具
- 日历提醒或后续订阅提醒能力

## 3. 数据结构设计

## 3.1 推荐方案

推荐采用 `date + time` 双字段方案。

### 前端类型建议

`types/index.ts`

```ts
export interface Countdown {
  id?: number;
  title: string;
  date: string;
  time?: string;
  category_id: number;
  user_id: number;
  is_pinned: boolean;
  repeat_cycle: number;
  repeat_frequency: '不重复' | '天重复' | '周重复' | '月重复' | '年重复';
  is_archived?: boolean;
  created_at?: string;
  updated_at?: string;
  days_left?: number;
  status_text?: string;
  repeat_text?: string;
}
```

`CountdownForm` 建议同步增加：

```ts
time?: string;
```

### 组件表单建议

`AddCountdown.vue` 中 `formData` 增加：

```ts
time: string;
```

建议格式：

- `HH:mm`

## 3.2 为什么不优先采用 datetime 单字段

不优先选 `datetime` 的原因：

- 当前项目已经稳定使用 `date`
- 直接替换成 `datetime` 会扩大影响面
- 旧数据兼容与迁移成本更高
- 页面已有大量日期处理逻辑可在保留 `date` 的情况下渐进升级

## 4. 兼容策略

## 4.1 老数据兼容读取

对于未返回 `time` 的历史数据：

- 前端读取时兜底为 `06:00`
- 用统一工具函数生成完整目标时间

建议提供公共函数：

```ts
getCountdownDateTime(countdown): Date
```

行为：

- `date + time` 存在：按完整时间解析
- 只有 `date`：按 `date 06:00` 解析

## 4.2 老数据兼容编辑

编辑老数据时：

- 弹窗中 `time` 回显为 `06:00`
- 用户不修改也允许保存
- 一旦保存，即补齐 `time`

## 4.3 数据迁移策略

建议采用“懒迁移”而非一次性强制迁移：

- 后端先支持 `time` 可空
- 前端先兼容老数据
- 老数据在编辑或重新保存时自然补齐

如果后续有统计依赖，也可追加一次数据库脚本，将空时间填充为 `06:00`。

## 5. 前端改造设计

## 5.1 AddCountdown.vue

### 需要改造点

- 增加时间选择 UI
- `formData` 增加 `time`
- 编辑模式回显 `time`
- 提交参数中增加 `time`
- `resetForm()` 设置默认时间

### 推荐交互

在“选择日期”下方新增“选择时间”：

- 使用 `picker mode="time"`
- 值为 `formData.time`
- H5 与微信小程序均较容易兼容

### 默认值建议

新增方法：

```ts
getCurrentTime(): string
```

返回当前时间的 `HH:mm`。

本次评审结论：

- 新建奇妙日默认时间取当前时间
- 历史老数据缺省时间使用 `06:00`

### 需要改造的方法

- `data()`
- `watch.visible`
- `handleSubmit()`
- `resetForm()`
- 新增 `onTimeChange()`
- 可能扩展 `formatDateDisplay()` 为 `formatDateTimeDisplay()`

## 5.2 CountdownCard.vue

### 需要改造点

- 支持显示时间
- 倒计时文案从纯天数扩展为更细粒度
- 同日事件按时间区分

### 展示建议

- 首页/列表卡片显示时间
- 可将日期与时间合并为一行，如 `03-10 08:30`

### 计算建议

将“目标时间”统一由公共函数计算，不在组件中直接拼接日期字符串。

## 5.3 首页 index.vue

### 需要改造点

- `futureCountdowns`
- `pastCountdowns`
- `countdownsWithDisplayDate`
- `getNextRepeatDate()`
- 排序逻辑

### 关键调整

原逻辑若依赖 `new Date(countdown.date)`，需替换为：

```ts
resolveCountdownDateTime(countdown)
```

### 排序建议

按以下顺序排序：

1. `is_pinned` 降序
2. 目标时间升序
3. `id` 或创建时间兜底

## 5.4 calendar.vue / detail.vue

### 需要改造点

- 日期详情区增加时间展示
- 同一日期多个事件按时间排序
- 详情页显示完整时间

本次评审确认：

- 首页展示时间
- 列表展示时间
- 日历页展示时间
- 详情页展示完整时间

## 6. 公共工具设计

建议新增统一时间工具模块，例如：

- `src/utils/countdownTime.ts`

建议提供函数：

### `normalizeCountdownTime(time?: string): string`

作用：

- 标准化时间
- 空值时返回 `06:00`

### `resolveCountdownDateTime(countdown): Date`

作用：

- 将 `date + time` 解析为完整 `Date`

### `formatCountdownDateTime(countdown): string`

作用：

- 统一页面展示格式

### `getCountdownDiff(target: Date, now: Date)`

作用：

- 返回剩余/已过的天、小时、分钟信息

文案输出规则建议：

- 当剩余时间大于等于 1 天时，输出 `还有 X 天`
- 当剩余时间不足 1 天时，输出 `还有 X小时X分钟`
- 已过场景先兼容现有逻辑，后续统一成公共格式化输出

### `getNextRepeatDateTime(countdown, now)`

作用：

- 针对重复事件，保留小时分钟并计算下次发生时间

## 7. 接口与服务层设计

## 7.1 前端接口参数调整

`apiService.createCountdown()` 与 `apiService.updateCountdown()` 入参增加：

- `time`

### 创建参数示例

```ts
{
  user_id,
  title,
  date,
  time,
  category_id,
  is_pinned,
  repeat_cycle,
  repeat_frequency,
  is_archived
}
```

## 7.2 后端接口要求

后端倒数日模型新增字段：

- `time`，类型建议 `varchar(5)`，格式 `HH:mm`

接口要求：

- 查询接口返回 `time`
- 新建接口支持 `time`
- 更新接口支持 `time`
- 老数据 `time` 允许为空

## 7.3 数据库存储建议

推荐字段：

- `date`：`DATE` 或字符串日期
- `time`：`VARCHAR(5)`

不建议本次直接改成完整 `DATETIME`，除非后端当前已具备成熟兼容能力。

## 8. 重复事件设计

## 8.1 当前风险

当前重复事件逻辑大概率只按日期计算，不保留时间。

## 8.2 升级目标

重复事件在推算下一次时，必须保留：

- 原始小时
- 原始分钟

示例：

- 原事件：`2026-03-10 08:30`
- 每周重复
- 下一次：`2026-03-17 08:30`

## 8.3 技术处理建议

不要再以字符串直接拼接处理重复，而是：

1. 先构造完整 `Date`
2. 根据重复规则做 `setDate / setMonth / setFullYear`
3. 输出新的完整时间对象

## 9. 测试方案

## 9.1 单项测试点

- 新建奇妙日时可选择时间
- 编辑奇妙日时可回显时间
- 未设置时间的老数据能正常打开编辑
- 同一天多个奇妙日按时间排序正确
- 倒计时结果在同一天内可区分已过/未到
- 重复事件保留小时分钟
- H5 与微信小程序时间选择器表现正常

## 9.2 兼容测试点

- 老接口不返回 `time` 时页面不报错
- `time` 缺失并按 `06:00` 兜底时显示正常
- 空字符串、非法时间值的兜底逻辑正确

## 9.3 回归测试点

- 新增/编辑/删除/归档流程
- 分类筛选
- 首页置顶逻辑
- 日历页查看
- 详情页展示

## 10. 分阶段实施建议

### 第一阶段：数据与表单打通

- 类型定义增加 `time`
- `AddCountdown.vue` 增加时间选择器
- 创建/编辑接口透传 `time`
- 老数据兼容兜底
- 新建默认时间取当前时间

### 第二阶段：展示与排序升级

- 首页卡片展示时间
- 列表页展示时间
- 详情页展示时间
- 同日排序优化
- 日历页同日时间排序

### 第三阶段：重复与倒计时升级

- 重复规则保留小时分钟
- 倒计时文案按“大于 1 天 / 不足 1 天”分级显示
- 公共时间工具抽离

## 11. 风险点

- 前端多个页面可能各自存在日期解析逻辑，改造时需统一收口
- 如果后端将 `date` 当字符串排序，加入 `time` 后列表顺序可能与前端计算不同
- 重复事件若存在边界日期，如月底、闰年，需要补测试用例
- 小程序与 H5 对 `new Date('YYYY-MM-DD HH:mm')` 的解析表现可能不一致，建议手动拆分构造 `Date`

## 12. 推荐最终决策

建议本次评审采用以下方案：

- 数据结构：`date + time`
- 时间精度：到分钟
- 旧数据兼容：缺省按 `06:00`
- 表单控件：`picker mode="date"` + `picker mode="time"`
- 新建默认时间：当前时间
- 展示范围：首页 / 列表 / 日历页均展示时间，详情页展示完整时间
- 倒计时文案：超过 1 天展示“还有 X 天”，不足 1 天展示“还有 X小时X分钟”
- 重复逻辑：保留原小时分钟
- 分阶段交付：先打通录入与存储，再升级展示和倒计时
