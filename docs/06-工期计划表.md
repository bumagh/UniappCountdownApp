# 奇妙日工期计划表

## 1. 计划说明

本计划表基于当前项目现状编制，适用于“已有 MVP 版本基础上进行规范化完善与发布优化”的场景。当前项目按照 **单人兼职开发** 估算，开发者同时承担产品、前端联调、测试与发布工作；后端基于 **BuildAdmin** 提供接口能力，并采用 **AI 辅助开发** 提升分析、编码、文档与排错效率。

## 2. 角色建议

- 独立开发者：1 人（兼职）
- 后端支撑：BuildAdmin 现成后台与接口体系
- AI 工具：用于需求整理、代码辅助、文档生成、问题排查

## 3. 阶段划分

| 阶段 | 目标 | 预计工期 |
|---|---|---:|
| 需求梳理与方案确认 | 梳理功能边界、文档、技术方案 | 4 天 |
| 技术治理与代码整理 | 统一缓存键、接口约定、适配逻辑 | 7 天 |
| 功能优化与缺陷修复 | 修复问题、补齐体验 | 10 天 |
| 测试与联调 | 回归、兼容性、小程序验证 | 7 天 |
| 发布与交付 | H5 部署、小程序提审、文档归档 | 4 天 |
| **总计** |  | **32 天** |

## 4. 分阶段计划

### 4.1 第一阶段：需求梳理与方案确认（第 1~4 天）

#### 工作内容

- 梳理当前已有功能
- 补齐软件工程文档
- 明确 H5 与小程序差异点
- 确认登录天数、登录态、版本检测等关键规则
- 整理 README 中历史待办、问题清单与订阅消息配置
- 明确后端 BuildAdmin 对接边界
- 输出发布范围与验收标准

#### 交付物

- 软件工程说明书
- 架构图 / 业务流程图
- 产品策划文档
- 工期计划表

### 4.2 第二阶段：技术治理与代码整理（第 5~11 天）

#### 工作内容

- 统一 `token` / `userToken` 等缓存键命名
- 统一 `loginDays` 的来源策略
- 梳理 API 调用错误处理
- 清理历史兼容代码与冗余逻辑
- 规范页面安全区适配方案
- 评估并接入字体大小调节设置能力
- 整理 README 与部署说明

#### 交付物

- 技术治理说明
- 已清理的核心代码
- 发布版配置

### 4.3 第三阶段：功能优化与缺陷修复（第 12~21 天）

#### 工作内容

- 优化首页列表与格子布局体验
- 优化登录流程和注册补全流程
- 优化个人中心信息展示
- 优化归档、置顶、分享细节
- 优化关怀模式适配
- 增加字体大小可调节能力
- 处理编辑按钮不明显问题
- 评估快捷添加 120 岁倒数日能力
- 评估各页面转发配置
- 测试闹钟应用联动可行性
- 修复高优先级 bug

#### 交付物

- 可提测版本
- 缺陷修复清单

### 4.4 第四阶段：测试与联调（第 22~28 天）

#### 工作内容

- H5 全链路测试
- 微信小程序真机测试
- 登录、倒数日 CRUD、分类、归档、分享测试
- 兼容性和异常路径测试
- 华为 nova 5 Pro 底部布局问题验证
- 订阅消息与模板消息配置联调验证
- 回归测试

#### 交付物

- 测试用例
- 测试报告
- 回归结果

### 4.5 第五阶段：发布与交付（第 29~32 天）

#### 工作内容

- 构建 H5 发布包
- 部署正式环境
- 上传微信小程序体验版 / 审核版
- 完成上线验收
- 整理交付文档

#### 交付物

- 线上 H5 版本
- 小程序审核版本
- 部署记录
- 项目交付文档包

## 7. 风险与缓冲

### 7.1 风险项

- 微信小程序登录与审核规则变化
- H5 微信分享签名问题
- BuildAdmin 现有接口字段与前端预期不一致
- 版本更新清缓存策略影响用户体验
- 多端兼容差异引发回归问题
- 单人兼职开发导致排期易受主业时间影响

### 7.2 缓冲建议

- 预留 4~6 天风险缓冲
- 小程序提审至少预留 1 个审核周期
- 关键路径功能提前联调
- 使用 AI 辅助完成文档、排查与重复性编码工作

## 9. 建议验收标准

- H5 与微信小程序均可正常运行
- 登录、注册、补全信息流程完整
- 倒数日新增、编辑、删除、置顶、归档正常
- 分类功能正常
- 首页、分类页、日历页、个人中心功能正常
- 累计登录天数显示正确
- 字体大小调节与关怀模式可用
- 分享与版本检查功能正常
- 文档完整可交付
